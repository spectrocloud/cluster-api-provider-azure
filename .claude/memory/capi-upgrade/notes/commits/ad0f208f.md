- **behavior:** Hardens the webhook server's TLS endpoint. Adds `TLSOptions` struct + `AddTLSOptions` flags + `GetTLSOptionOverrideFuncs` + `GetDefaultTLSCipherSuits` to main.go and wires the overrides into `webhook.NewServer(webhook.Options{TLSOpts: tlsOptionOverrides})`. Net config (after f9cfc76b removed the flag registration): **MinVersion = MaxVersion = TLS 1.2 pinned** (empty `TLSMinVersion` → component-base default TLS12; MaxVersion set to the same value, so TLS 1.3 is deliberately disabled — cipher-suite config is only honored on ≤1.2) and **exactly 4 ECDHE-GCM suites**: TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256. This is the CoreSec-audited scanner posture — the contract is "webhook endpoint only ever negotiates TLS1.2 + these suites", baked in as defaults, not operator-supplied flags.
- **pr/ticket context:** JIRA only (above). The go.mod (+135) / go.sum (+670) hunks in this replayed commit are a replay artifact — they re-add stale v1.3-era deps (duplicate `go-logr`, `prometheus/client_golang`, old azure-sdk) and are NOT part of the TLS fix.
- **parity vs v1.26.0:** **PARTIAL — main.go part FORK-ONLY must-carry; go.mod/go.sum part must be dropped.** v1.26.0 gets TLS config from CAPI `flags.GetManagerOptions(managerOptions)` (`--tls-min-version`, `--tls-cipher-suites` flags exist upstream) but the DEFAULTS are permissive (Go default suites, no MaxVersion pin). Palette deployments pass no TLS flags, so on a plain pick-less upgrade the webhook endpoint would silently regress to unhardened TLS and fail the next bulwark scan.
- **resolution guidance:** Take ONLY the main.go functions (`TLSOptions`, `GetTLSOptionOverrideFuncs`, `GetDefaultTLSCipherSuits`) and the `TLSOpts: tlsOptionOverrides` wiring; discard the go.mod/go.sum hunks entirely (target go.mod is authoritative; Patch-G CVE gate re-validates). Do NOT reintroduce `AddTLSOptions` flag registration — CAPI's `flags.AddManagerOptions` already registers `--tls-min-version`/`--tls-cipher-suites`, and a duplicate pflag registration panics at startup (this is exactly why f9cfc76b removed it). In v1.26.0 main.go, replace `tlsOptions` from `GetTLSOptionOverrideFuncs` result at the `webhook.NewServer` site (discard the upstream-flag-derived value, or merge: fork overrides win). Add `k8s.io/component-base` (cliflag) import. Verify with an in-cluster `openssl s_client`/testssl pass at T2/CBT if feasible.
