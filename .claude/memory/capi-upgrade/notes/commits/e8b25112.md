Reason: the Sequoia team's AzSecret **emulation** environment wraps region eastus2 under the name "ussec"; Azure API calls need the real region name. Initially UNGUARDED (mapped everywhere).

Author agreed: check the simulator/env first, else a real 'ussec' region in production AzSecret would be wrongly remapped while online. That produced 32e8a1f1.
- **parity vs v1.26.0:** **FORK-ONLY must-carry (in guarded final form).** v1.26.0 has no region aliasing. Surviving form at S: mapping applied only when `AzureEnvironment == "AzureUSSecretCloud"` AND ResourceManagerEndpoint/BaseURI contains `.scombine.scloud` (emulator detection).
- **resolution guidance:** Land as part of the #118+#121+#122 location-mapping unit: util/azure additions (+33 net) + guarded call sites (cluster.go Location() at S ~line 1204, machinepool.go Location() wrapper, managedcontrolplane.go Location()). Never land the unguarded version — it breaks real AzSecret (reviewer-confirmed risk).
