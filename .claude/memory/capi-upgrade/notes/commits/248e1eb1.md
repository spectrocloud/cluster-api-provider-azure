- **behavior:** Flips the `--webhook-port` flag default from upstream's 9443 to **0** and makes it a mode switch in `main()`: `webhookPort == 0` → `registerControllers(ctx, mgr)` ONLY; `webhookPort != 0` → `registerWebhooks(mgr)` ONLY. This is what lets palette deploy the SAME image as two Deployments — a controller pod (no `--webhook-port` arg) and a webhook pod (`--webhook-port=9443`). The webhook Service (`capz-webhook-service` in `capi-webhook-system`, targetPort `webhook-server`) fronts the webhook pod.
- **pr/ticket context:** none; behavior inferred from diff + spectro manifests. The generated `spectro/generated/core-{base,global}.yaml` controller Deployments pass NO `--webhook-port` (controllers-only mode); the `--webhook-port=9443` arg for the webhook replica is injected on the palette deployment side (no occurrence in spectro/ inputs at S).
- **parity vs v1.26.0:** **FORK-ONLY must-carry.** v1.26.0 `main.go` registers controllers AND webhooks unconditionally in one process, default `--webhook-port` is 9443. Upstream's new `--disable-controllers-or-webhooks` flag only disables two specific controllers (ASOSecret, AzureJSONMachine) — it is NOT a controller/webhook split and cannot replace this.
- **resolution guidance:** File `main.go`. Preserve BOTH halves: (a) default `0` on the webhook-port flag, (b) the if/else on `webhookPort` around `registerControllers` / `registerWebhooks` (v1.26.0 calls both back-to-back at ~line 391). Getting the default wrong is catastrophic in a specific way: if the default reverts to 9443, palette's controller Deployment (which passes no flag) would take the `registerWebhooks`-only branch and run NO reconcilers at all — total reconcile outage. Also note both pods carry label `cluster.x-k8s.io/provider: infrastructure-azure` which the webhook Service selects on; the controller pod must not answer :9443. Verify at T1: binary with no args registers controllers only; with `--webhook-port=9443` registers webhooks only. Regression Watch HIGH is justified — keep it.
